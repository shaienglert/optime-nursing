## Minimum inputs before first search

Search should start as soon as there is enough information to avoid a meaningless or unsafe universe. Minimum means:

1. Who is moving: one person or couple.
2. Geography broad enough to define a market.
3. Current level of care / critical ADL-mobility-cognition needs sufficient for basic eligibility.
4. Any known non-negotiable clinical requirement.
5. Any explicit MUST already volunteered: budget ceiling, couple co-residence, memory care, rehab, language necessary for care communication, etc.

Do NOT require lifestyle, activity, dining, social, room or family-communication questions before first search unless the person has already declared them MUST.

## Next-Best-Question rule

A question may be asked only if all are true:

1. The value is currently UNKNOWN or materially ambiguous.
2. It cannot be obtained more reliably from provider/public evidence.
3. The answer could change one of: eligibility, relative ordering, important trade-off, or required transition support.
4. The question is lawful, necessary and framed around the underlying need rather than a protected-trait proxy.
5. Its expected decision value is greater than the burden of asking now.

Priority order:

A. Resolve potential HARD-GATE unknowns that affect safety/eligibility.
B. Resolve HIGH-impact unknowns that split the actual candidate set.
C. Resolve MEDIUM variables only when they differentiate otherwise strong candidates.
D. Do not ask CONTEXTUAL variables unless the resident/family has signaled importance or market results make them decision-relevant.
E. Never ask solely to fill a profile.

## Market-driven example

Initial understanding: post-stroke resident, walker, medication support, socially engaged, Miami area.

First search produces 24 clinically eligible facilities. If 22 support medication and walker mobility, asking more about those variables has almost no current decision value. If only 8 have verified on-site rehab and rehab need is UNKNOWN, ask about current PT/OT/speech goals. If the top 8 are otherwise similar but half allow flexible meal timing and the resident has not expressed a routine preference, do not ask unless that difference becomes meaningful to the family.

## UNKNOWN behavior

UNKNOWN is not a negative answer. For a MUST variable:
- Known mismatch => exclude.
- Known match => eligible.
- Unknown => eligible when safe to do so, lower confidence / ranking and expose the uncertainty.

If safety requires proof of a capability before recommendation, UNKNOWN may prevent FINAL recommendation but should remain distinct from mismatch.

## Confirmation rule

When the system infers a preference from browsing, rejected facilities, tours or repeated choices:
- store hypothesis as INFERRED;
- ask concise confirmation only when it could matter to future recommendations;
- on user approval => CONFIRMED;
- on rejection => CONTRADICTED;
- never overwrite the original evidence/history.

## No conventional intake questionnaire

The desired sequence is:

Initial story / available records -> concise understanding summary -> user confirms/edits -> first real market search -> result-set intelligence -> Next-Best-Question -> recompute -> repeat only while information has material decision value -> Decision Report / OPTIMER.

The Tree of Understanding should reflect knowledge sufficiency, not the number of questions answered.
