# Modern accessible visual language

Classification: B — owner-requested presentation completion, October 4, 2026.
RELEVANT EXISTING PRINCIPLES: PR-001, PR-002, PR-003, PR-005, PR-009.
DOES THIS CHANGE ALTER ANY PRINCIPLE? NO.
OWNER APPROVAL REQUIRED? NO.

Apply the supplied off-white/graphite/sapphire/coral direction to the existing
public matching journey. Keep conversational personal results and questionnaire
gates. The hero starts the existing relationship → age → intake flow, rather than
adding a search field that bypasses understanding or does nothing. Process cards
explain the journey; facility categories never become automatic match gates.
Do not invent family testimonials, a contact phone, Miami coverage or real-time
appointments. Keep existing research and administrative routes reachable in
secondary navigation. Use visible keyboard focus, 48px primary touch targets,
readable body text and reduced-motion handling. Coral is a decorative accent;
small text uses a darker accessible tone instead.

Validation: production frontend build/TypeScript, fourteen targeted frontend
tests, lint on homepage/header/icons/guidance and intake/UI validator pass.
Local Chromium verifies homepage person → age → intake, mobile menu, large text
at 390px without horizontal overflow; existing mocked confirmation/results/
visit/quote journeys also pass. Measured color ratios: white/sapphire 7.15:1,
graphite/off-white 15.51:1, secondary text/off-white 6.51:1,
dark terracotta text/off-white 5.82:1. This is targeted verification, not a full
accessibility audit or live production/provider validation.
